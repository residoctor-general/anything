# 総合健康管理アプリ（構想）

一般向けのiPhoneアプリ。健康データの入力はAI（Muse）とSiriに任せ、アプリは総合的に「見る」ことに徹する。出典は2026-11-18の日誌（AI秘書セッション経由）。

## 考え方
- 薬機法にかからない一般向けの領域で作る。不安をあおる商売はしない。
- 入力の窓口はMuseとSiri。アプリは表示、グラフ化、相関の計算をする。
- 健診結果はMuseに読ませて数値にする。アプリには読み込み機能もAIも要らない。
- 個人情報を預からない。運営側にデータベースを持たない。ログインも不要。

## 表示したいもの
- 健診結果と病院の検査結果（PDFで閲覧。血液検査は表とグラフにする）
- 選んだ項目を並べてグラフにする（例：睡眠時間と心拍変動）。項目どうしの相関を計算し、その結果にMuseがコメントする
- お薬手帳（PDF）、血圧（アプリから入力も可）、排便、食事、睡眠、カフェイン、スクリーンタイムなど
- 世の中の健康アプリの機能を洗い出し、表示する項目を利用者が選べるようにする案もある

## 調査で分かったこと
- **App Store審査ガイドライン 5.1.3(ii)：健康情報をiCloudに保存してはならない。** iCloudにデータを置く設計は使えない。
  - 代わりの案：Appleのヘルスケアアプリのデータをデータの置き場にする（血圧、睡眠、心拍変動、カフェイン、栄養素、症状などはすでに項目がある）。ヘルスケアアプリにない項目は端末の中だけに保存する。
  - 利用者が自分でiCloud Driveに置いたファイルを、その都度開く形が許されるかは要確認。
- 課金にログインは不要（App Storeの月額課金はApple IDで管理される）。ガイドライン5.1.1(v)も、アカウント機能が本質でないアプリはログインなしで使えるようにすることを求めている。
- App Storeには販売者名（法人名または個人名）が必ず表示される。特定商取引法の表示がどこまで必要かは要確認。

## お金
- 月100〜300円を想定。月200円で1000人なら年240万円。
- 懸念：表示するだけのアプリに払うか。かなりニッチ。無料で配って広告代わりにする手もある。

## 差別化の案
- 日本の健診項目と検査値に強いこと。検査値の項目からresidoctorの「検査データ」の記事に飛べるようにする（医師が作ったアプリとしての信頼と、サイトへの集客）。

## 未決定・要確認
- **「Muse」がどの製品か**（AIとの連携の方式が決まる。MCPかSiri経由か）
- 「Museでそれができるか」の確認（最初の一歩）
- 競合の調査（海外には相関を出すアプリとしてExistやBearableがある。日本向けで健診まで扱うものは要調査）
- 健康アプリの機能の洗い出し → 入れるものを選ぶ → 見せ方を決める
