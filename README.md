# 個人用の診療サポート道具

医師本人が個人で使うための道具。事業化はしない（医療機器として承認を取る段階は、個人会社には現実的でないと判断したため）。

## 作るもの

### 1. 個人情報を伏せるページ
- カルテの文章を貼ると、ブラウザの中だけで個人情報を伏せる。外には送らない。
- **何も保存しない**：病院のPCのブラウザには、辞書・入力した文章・設定などを一切残さない。
- 伏せ方は「プログラムで伏せる → なぞって手で伏せる」の2段構え。
  - ブラウザ内AIは使わない（数GBのダウンロードが必要で、病院のネットワークや「何も保存しない」決まりと合わないため）。
- 規則で伏せる対象：患者ID、電話番号、日付（「○日前」に変換）、年齢（「70代」に丸める）、住所、氏名（「様」「さん」などの目印と姓の辞書）。施設名・医師名は辞書を使わず、目印（「病院」「クリニック」「医院」「先生」「Dr.」「医師」など）で見つける。
- 送信前の確認画面で、伏せた箇所と怪しい箇所を色で表示する。
- 確認画面で文字をなぞって選び「伏せる」ボタンを押すと、手で伏せられる。誤って伏せた箇所は、選んで「元に戻す」で戻せる。
- ボタン：コピー、QRコード表示、削除（入力と結果をすべて消す）
- 珍しい病気や特徴的な経過の症例は、名前を伏せても特定されうるので、表現をぼかすか相談の対象外にする（運用上の決まり）。
- 病院のPCではClaudeにログインしない。
- 最初は架空のカルテで試し、カルテの書き方の癖に合わせて規則を調整する。

### 2. 相談役（全分野）
- まず residoctor.com を参照し、記事がなければ他の情報源を参照する。
- 回答は決まった型を使わず、質問に合わせる（詳しくは下の B2）。
- ガイドラインの本文が読めなかった場合は「本文は確認できなかった」と明記する。

### 3. residoctorの記事の不備を知らせる機能
- 相談中に記事が古い、または間違っていると分かったら、general@residoctor.com 宛てに知らせる。
- メールに入れる内容：記事のURL、問題の箇所、正しい情報とその出典、重要度（誤りか、古いだけか）

## 決定した事項（2026-11-18）
- **A1** 持ち出し方：病院のPCで伏せる → QRコードでiPhoneへ（スマホはiPhone）。
  - QRコードの中身は「受け取り用ページのURL＋伏せた文章」にする。文章はURLの「#」以降に入れるので、ページの置き場所のサーバーにも送られない。
    - 理由：文章だけのQRコードをiPhoneのカメラで読むと、タップしたときにウェブ検索に送られてしまうことがあるため。
  - iPhoneで受け取り用ページが開き、文章が表示される → コピーボタン → Claudeアプリのプロジェクトに貼る。
  - QRコード1枚に入る量には上限がある（日本語で1,000字前後が目安）。長い文章は複数枚に分け、受け取り用ページでつなげる。
  - カルテ画面をiPhoneのカメラで直接読み取る方法は採用しない（院内でカルテ画面の撮影は認められない見込みのため）。
- **A2** ブラウザ内AI：使える環境でだけ使うオプションにする。
- **A3** 置き場所：まずGitHub Pagesに置く。residoctor.com の下（例：residoctor.com/mask）に移すかは、サイト担当のエージェントと相談して後で決める。ページはデータを保存しないので、置き場所は後から変えられる。検索エンジンには載せない（noindex）。
- **B1** 相談役の仕組み：おまかせ（Claudeのプロジェクト機能＋ウェブ検索で進める）。
- **B3** 外部情報の優先順位：国内の学会ガイドライン → PMDAの添付文書 → 海外のガイドライン → PubMed。参照しない：個人ブログ、まとめサイト、製薬会社の宣伝資料。査読前の論文は「参考程度」と明記する。
- **C1** メール：Gmailに下書きを作り、送信は本人が行う。
- **C2** 判断基準：「誤り」＝最新の添付文書や現行ガイドラインと食い違う。「古い」＝記事の作成後にガイドラインが改訂された、または薬の適応追加・販売中止などが記事に入っていない。
- **B2** 回答の型：決まった型は使わず、質問に合わせて答える。
  - 毎回守る決まり：根拠の出どころ（residoctor／外部情報／AI自身の知識）を区別して書く。注意点がある場合は必ず書く。
  - 関係するときだけ触れる項目：腎機能・肝機能に応じた用量調整、薬の飲み合わせ、次の受診時期・紹介の目安
  - 患者さんへの説明用の一言は入れない。

## 伏せるページ（mask/）の使い方
- 公開先（GitHub Pagesを有効にした後）：https://residoctor-general.github.io/anything/mask/
- 手順：文章を貼る → 「伏せる」 → 色付きの箇所を確認し、必要ならなぞって「伏せる」／「元に戻す」 → 「QRコードを表示」 → iPhoneのカメラで読む → 受け取りページで「コピー」 → Claudeに貼る
- 使い終わったら、PCでもiPhoneでも「削除」を押す。

### ファイル
- `mask/index.html` `mask/app.js`：伏せるページ（PC用）
- `mask/rules.js`：伏せる規則
- `mask/codec.js`：QRコード用に文章を詰める・戻す
- `mask/r.html` `mask/receive.js`：受け取り用ページ（iPhone用）
- `mask/vendor/qrcode.js`：QRコードを作る部品（qrcode-generator、MITライセンス）
- `tests/`：架空のカルテ文と確認用スクリプト（`node tests/run.js`、`node tests/cases.js`、`node tests/check_nopii.js`）

### 安全のための仕組み
- ページの設定で、外部との通信を禁止している（Content-Security-Policy の connect-src 'none'）。
- 病院のPCには何も保存しない。iPhone側だけ、QRコードが複数枚のときに限り、そろうまで一時的に保存する（30分で自動的に消える。そろったら即削除）。
- QRコードの文章はURLの「#」以降に入れるので、サーバーには送られない。受け取りページを開いたら、すぐにアドレス欄からも消す。
- 検索エンジンには載せない（noindex）。

### QRコード1枚に入る量
- 実際のカルテ文で、1枚あたり約500〜600字（伏せた後の文章）。それを超えると自動的に複数枚に分かれる。
